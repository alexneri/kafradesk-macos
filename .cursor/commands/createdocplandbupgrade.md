# Documentation Plan for DB upgrade

Create a documentation plan to update the backend upgrade guides for the specified version. In this case, you will need to analyse the files in the liquibase folder for the database upgrades per service. You will need to check each .xml file to find the database tag, i.e. `tagDatabase tag="2025.09"`, replace the version with the specified version in this chat and add the service name to the plan. As an example, For 2025.09-LTS, the file is `backbase-bom/2025.09-LTS/liquibase/transaction-manager/db/changelog/db.changelog-8.0.0.xml`, with the information in `<changeSet id="2025.09_016" context="upgrade_2025_08_to_2025_09" author="backbase">`, with `changeSet id="2025.09_016"` indicating that an upgrade is available for the`transaction-manager`service. The file to be updated is`upgrade/no-version/backend/<version>.adoc`, as an example if the update is for 2025.09-LTS, the file to be updated is`partials/upgrade-lts-lts-backend/2025.09-LTS.adoc`. There is a section called "Database upgrades" that needs to be updated with the changes found in the liquibase folder. Using our current example, the update would be "| Accounts and Transactions | transaction-manager     | `db.changelog-8.0.0.xml`". Use the matrix in `samples/2025.10 Banking release notes - Data.csv` to map the service name to the actual service name, i.e "transaction-manager" mapped under "Accounts and Transactions". If the Data from the CSV matrix is vague or not clear, you can search from the other Backend Database Upgrade guides to find the historically correct service name. Create the documentation plan in a new markdown file (*.md) in ~/Documents/TicketContext/.

Constraints {
    Follow the documentation plan template in ~/Documents/TicketContext/rules/docplan-template.mdc. The documentation repository is in ~/GitHub/documentation/.
}
